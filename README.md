<h1 align="center">FairFlow AI</h1>
<p align="center"><strong>결제·구독 여정의 다크패턴 위험을 살펴보는 Figma 플러그인</strong></p>
<p align="center"><a href="#figma에서-실행">Figma에서 실행</a> · <a href="#점검-대상">점검 대상</a> · <a href="#예제-데이터">예제 데이터</a></p>

FairFlow는 선택한 프레임에서 프로토타입 연결을 따라가며 유료 옵션의 초기 상태, 선택 버튼의 위계, 가격 변화를 점검합니다. 결과에서 근거 레이어를 누르면 캔버스의 해당 위치로 이동합니다. 디자이너가 제안에 따라 시안을 수정한 뒤 같은 여정을 다시 검사할 수 있습니다.

## Figma에서 실행

1. 저장소를 내려받아 압축을 풀거나 복제합니다. 실행용 번들이 들어 있습니다.
2. Figma 데스크톱의 디자인 파일에서 **Plugins → Development → Import plugin from manifest…** 를 열고 저장소 루트의 `manifest.json`을 선택합니다.
3. 검사할 시작 프레임 하나를 선택하고 **Plugins → Development → FairFlow AI**를 실행합니다. 첫 진입 상태가 필요한 검사에는 Figma의 프로토타입 시작점을 사용합니다. 패널에서도 선택한 프레임이 실제 첫 화면임을 확인할 수 있습니다.
4. 결과의 근거 레이어를 눌러 시안을 확인합니다. 수정 후 **다시 검사**를 누르면 처음 검사한 프레임에서 다시 시작합니다.

## 빠른배송 디자인 제안

빠른배송 여정을 검사한 다음 **배송 수정안 만들기**를 누릅니다. 플러그인은 현재 디자인의 배송 선택 컴포넌트를 사용해 두 개의 편집 가능한 수정안을 만듭니다. 최소 수정안은 기존 배치에서 일반배송을 기본으로 선택합니다. 배치 변경안은 일반배송과 빠른배송을 한 영역에 모아 가격을 비교하기 쉽게 배치합니다.

- **캔버스에서 나란히 보기**는 생성 시점의 원본 복사본과 두 수정안을 함께 보여줍니다. 패널에서 **원본**을 누르면 실제 원본 프레임으로 이동합니다.
- **선택 없이 계속**, **일반배송**, **빠른배송** 중 하나를 고르면 각 안의 배송비와 주문 총액이 표시됩니다. **주문 화면 보기**를 누르면 해당 프로토타입의 확인 프레임으로 이동합니다.
- **수정안 재검사**는 실제 원본과 두 수정안의 연결을 다시 읽습니다. 확인 화면에서 총액을 지우면 그 안의 합계를 **확인 필요**로 표시합니다.

일반배송과 빠른배송은 선택 상태를 바꿀 수 있는 Figma 인스턴스여야 합니다. 각 선택지와 기본 진행 버튼을 총액이 표시된 주문 확인 화면에 직접 연결하세요. 비교 패널은 현재 플러그인 실행 중에 유지되며, 생성한 프레임은 파일에 남습니다. 현재 제공하는 유료 기능은 결제와 외부 모델 없이 실행하는 미리보기입니다.

## 점검 대상

| 유형 | 확인하는 것 |
| --- | --- |
| 특정옵션 사전선택 | 사용자가 고르기 전에 별도 유료 옵션이 선택되어 있는지 |
| 잘못된 계층구조 | 버튼의 시각적 차이로 한 가지 선택만 가능하거나 필수처럼 보이는지 |
| 순차공개 가격책정 | 확정된 필수 비용이 첫 가격 표시에서 누락되고 이후에 공개되는지 |

MVP는 한국어 문구와 원화 가격, Figma 레이어 속성을 편집기 안에서 규칙으로 분석합니다. 실제 과금 여부나 조건부 분기처럼 시안만으로 판단하기 어려운 항목은 **정보 부족**으로 표시합니다. 시각적 크기와 대비는 검토할 후보를 찾는 지표이며, 법령은 선택지를 오인할 우려 등 해당 조항의 요건을 함께 다룹니다. [전자상거래법 제21조의2](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1031806317)

예를 들어 `빠른배송 +5,000원`이 표시된 라디오 컴포넌트는 첫 진입 시의 선택 속성과 그곳으로 이어지는 클릭을 함께 검사합니다. 가격은 첫 표시와 주문 명세의 상품가·필수 비용·총액을 대조합니다. 변수에 따른 전환이나 오버레이 등 실행 조건을 확인해야 하는 연결은 패널의 검사 범위 안내에서 확인할 수 있습니다.

[JSONL 예제 12건 보기](data/fairflow_examples.jsonl)

세 유형마다 위험 신호, 수정안, 혼동하기 쉬운 정상 사례, 정보 부족 사례를 하나씩 담았습니다. 예를 들어 빠른배송이 체크된 동일한 화면이라도, 첫 진입부터 켜져 있는 경우와 사용자가 직접 선택한 경우는 다른 라벨을 갖습니다.

- `input`에는 화면 상태와 클릭 전이를, `target`에는 라벨·근거 노드·수정안을 담습니다.
- 학습·검증·테스트를 나눌 때는 같은 `group_id`의 변형을 함께 배정합니다.

## 개발

Node.js 22 환경에서 다음 명령으로 번들을 다시 만들고 테스트합니다.

```sh
npm ci
npm test
```

`npm run build`는 `src/main.js`에서 Figma가 읽는 `dist/code.js`를 생성합니다. 패널은 `ui.html`입니다. 매니페스트의 ID는 로컬 개발용이며, Community에 게시할 때는 Figma가 발급한 ID를 사용합니다. [Figma 플러그인 매니페스트](https://developers.figma.com/docs/plugins/manifest/)

데스크톱에서 세 유형을 재현하려면 `npm run build:qa`로 테스트용 플러그인을 만들고 빈 디자인 파일에서 실행하세요. 빠른배송, 멤버십, 상품 가격 여정을 만들고 패널에서 근거 레이어를 선택한 뒤 수정 전후의 판정을 비교합니다. [데스크톱 테스트 사용법](qa/README.md)
