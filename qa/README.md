# Figma Desktop 여정 테스트

프로젝트 루트에서 `npm ci`와 `node qa/build.mjs`를 실행합니다. Figma Desktop에서 편집 가능한 Design 초안을 연 다음 **Plugins → Development → Import plugin from manifest…**에서 `qa/build/manifest.json`을 고릅니다.

**FairFlow Desktop QA → 세 여정 테스트 실행**을 누르면 현재 페이지에 편집 가능한 프레임 8개와 배송 선택 컴포넌트 하나를 만들고, 운영 플러그인과 같은 결과 카드와 버튼으로 각 여정을 검사합니다. 다시 실행하면 같은 페이지의 테스트 레이어를 재사용합니다. 기록된 테스트 레이어를 지웠다면 기존 작업 오른쪽에 여정 세 개를 새로 만듭니다.

| 여정 | 위험 상태 | 수정 후 |
| --- | --- | --- |
| 빠른배송 | 첫 화면에서 +5,000원 빠른배송이 선택됨 | 무료 일반배송 기본 선택. 기본 진행 버튼이 일반배송 확인으로 이동 |
| 잘못된 계층구조 | 기본 요금 버튼이 145 × 22px, 회색 9px 문구 | 버튼 316 × 52px, 짙은 색 16px 문구. 각 버튼의 목적지 유지 |
| 순차공개 가격책정 | 상품 카드 29,900원과 필수 고정 배송비 3,000원을 합쳐 주문 총액 32,900원 | 카드에 배송비 포함 32,900원 표시 |

각 실행은 원본 패널의 **선택한 프레임 검사**, **근거 레이어**, **다시 검사** 버튼을 누릅니다. 근거마다 먼저 캔버스를 이동해 해당 레이어를 화면 밖에 둡니다. 근거 버튼을 누른 뒤 선택된 레이어 ID와 뷰포트 안에 다시 나타난 레이어를 확인합니다. 테스트가 근거 선택을 유지한 채로 디자인을 수정하면, 재검사가 기존 시작 프레임에서 같은 유형의 카드를 **신호 없음**으로 바꾸는지 검사합니다. 위험 사례에서 해당 유형만 경고했는지, 수정 후 다른 경고가 남았는지도 검사합니다.

**개별 실행 · 검증 기록**에서 실행 결과 JSON을 복사할 수 있습니다. 중단되면 실패한 단계와 이미 확인한 레이어 ID가 남습니다. 여정별 **위험**으로 원래 조건을 복원하거나 **수정**으로 현재 선택을 유지하면서 수정안을 적용할 수 있습니다. 일반 사용자용 플러그인에서 수동으로 확인하려면 **위험**으로 시작 프레임을 선택한 다음 프로젝트 루트의 manifest로 설치한 **FairFlow AI**를 엽니다.

`qa/build`는 로컬 생성물입니다. 제품 코드나 UI를 변경하면 `node qa/build.mjs`를 다시 실행하세요. 빌드 및 Node 테스트만으로는 데스크톱 실행 결과가 만들어지지 않습니다.

## 빠른배송 디자인 제안 검증

**배송 수정안 테스트**는 무료 일반배송과 5,000원 빠른배송이 각각 합계 29,900원과 34,900원으로 이어지는 예제를 사용합니다. 제품 패널에서 수정안을 생성하고, 원본과 두 안을 나란히 확인하고, 세 가지 배송 선택에서 합계와 확인 프레임 이동을 비교합니다. 원본의 선택과 연결이 유지되는지, 두 안이 기존 배송 컴포넌트와 연결된 채 별도의 주문 화면으로 이어지는지도 검사합니다. 마지막으로 **수정안 재검사**를 눌러 빠른배송 사전선택 신호가 해소됐는지 확인합니다.

## 데스크톱 검증 기록

2026년 11월 19일 Windows Figma Desktop 126.9.13에서 세 여정을 실행했습니다. 위험 상태에서는 해당 유형의 신호가 1건씩 떴습니다. 근거 버튼을 누를 때마다 화면 밖의 레이어가 화면 안으로 들어오고 실제 선택 ID가 일치했습니다. 수정 후에도 마지막 근거를 선택한 상태로 같은 시작 프레임을 재검사했고, 세 유형 모두 **신호 없음**으로 바뀌었습니다.

| 실제 검증 여정 | 화면 수 | 연결 수 | 근거 버튼 검증 |
| --- | ---: | ---: | ---: |
| 빠른배송 | 3 | 3 | 1/1 |
| 잘못된 계층구조 | 3 | 2 | 2/2 |
| 순차공개 가격책정 | 2 | 1 | 4/4 |

첫 실행에서 프레임은 생성됐지만 패널이 응답을 표시하지 못했습니다. Figma가 전달한 메시지를 패널의 바로 위 iframe에서 왔는지로 검사하던 조건을 없애고, Figma가 문서화한 `event.data.pluginMessage`로 읽도록 수정한 뒤 같은 초안에서 다시 실행했습니다. [Figma UI 메시지 문서](https://developers.figma.com/docs/plugins/creating-ui/#sending-a-message-from-the-plugin-code-to-the-ui)

같은 데스크톱에서 **배송 수정안 테스트**도 실행했습니다. 처음에는 라디오의 빈 테두리 레이어를 별도 선택지로 세어 생성 버튼이 표시되지 않았습니다. 문구가 없는 장식 레이어를 제외한 뒤 세 화면의 가로 정렬, 기존 컴포넌트 연결, 각 안의 독립 주문 확인 프레임, 아래 합계와 재검사 결과를 확인했습니다.

| 배송 선택 조건 | 원본 | 최소 수정안 | 배치 변경안 |
| --- | ---: | ---: | ---: |
| 선택 없이 계속 | 34,900원 | 29,900원 | 29,900원 |
| 일반배송 선택 | 29,900원 | 29,900원 | 29,900원 |
| 빠른배송 선택 | 34,900원 | 34,900원 | 34,900원 |
| 재검사 | 위험 신호 | 신호 없음 | 신호 없음 |

## 계층구조·가격책정 제안 검증

**계층구조·가격 수정안 테스트**는 기존 버튼과 상품 카드 인스턴스가 들어 있는 별도의 예제를 사용합니다. 2026년 11월 19일 Windows Figma Desktop 126.9.13에서 원본 사본과 두 수정안이 가로로 정렬되고, 수정안이 원본과 같은 메인 컴포넌트를 참조하는 것을 확인했습니다.

| 여정 | 원본 | 최소 수정안 | 배치 변경안 |
| --- | --- | --- | --- |
| 멤버십 버튼 | 유료 선택은 멤버십 접수로, 기본 선택은 기본 요금 확인으로 이동 | 두 목적지의 복제본에 각각 연결 | 기본 선택을 먼저 보여주고 두 목적지의 복제본에 각각 연결 |
| 유리컵 필수 배송비 3,000원 | 첫 가격 29,900원, 결제 단계에서 배송비와 총액 32,900원을 처음 공개 | 첫 상품 화면에서 배송비와 총액 32,900원 공개 | 첫 상품 화면과 상세 단계에서 상품 소계, 배송비, 총액 표시 |
| 두 유형의 재검사 | 위험 신호 | 신호 없음 | 신호 없음 |

비교 패널에서 계층구조의 목적지 6개와 가격책정의 단계 9개를 열어 각 Figma 프레임이 선택되는지 검증했습니다.

## 빠른배송 오버레이 검증

**배송 오버레이 테스트**는 실제 배송 화면과 주문 확인 화면을 렌더링하고, 수정안 표시 강도·원본 보기·변경 레이어 이동을 검사합니다. 원본과 두 수정안에서 선택 없이 진행, 일반배송, 빠른배송을 각각 실행합니다. 채택 후에는 편집 가능한 프레임에 같은 컴포넌트와 배치가 남고 양쪽 주문 경로가 채택안 내부로 연결되는지 독립적으로 다시 읽습니다.

2026년 11월 19일 Windows Figma Desktop 126.9.13에서 새 패널로 재검증했습니다. 접힌 **시안 만들기 및 비교** 영역을 연 뒤 변경 레이어 6개로 이동하고 배송 경로 9개를 확인했습니다. 배치 변경안을 채택하자 기존 배송 컴포넌트로 연결된 편집 가능한 여정이 생성됐습니다. 원본은 **위험 신호**, 채택안은 **신호 없음**으로 확인됐습니다.

수동 검사 화면도 같은 데스크톱에서 확인했습니다. 프레임을 선택한 뒤 **검사**를 눌러야 세 유형의 결과가 나왔습니다. 위험 카드의 전자상거래법 조항, 수정 대안, 근거 레이어 이동과 수정 후 재검사가 통과했습니다. 계층구조·가격책정 시안과 빠른배송 비교에서 실제 프레임 이미지도 표시됐습니다.
