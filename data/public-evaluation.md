# 공개 서비스 사례 평가

2026년 11월 19일 기준으로 공개 자료 12건을 [FairFlow 입력 형식](fairflow_public_cases.jsonl)에 옮겨 기존 규칙과 현재 플러그인에 포함된 로지스틱 회귀를 실행했다. 국내 조사·시정 화면 5건, 서비스 안내서의 결제·예약 화면 2건, 현재 공개 상품 페이지 2건, 해외 규제기관 화면 3건을 사용했다. 이 자료와 라벨은 학습에 사용하지 않았다.

문구, 가격, 선택 상태와 공개 자료에서 확인할 수 있는 화면 순서만 기록했다. 자료가 동일 상품의 화면 순서를 보여주지만 버튼 문구를 가린 경우에는 해당 전이의 문구를 비웠다. 판정은 Figma 패널과 같은 분석 함수에 이 입력을 전달한 결과다. 웹사이트 스캔이나 실제 결제는 진행하지 않았다.

`reference`는 공개 자료가 설명한 위험이나 해당 경로에서 확인한 정상 동작을 뜻한다. 해외 소장 사례는 제기된 문제를 기준으로 했고, 결제·과금 정보가 없는 현재 상품 페이지 두 건의 값은 비웠다.

기존 규칙은 12건 모두 판정을 보류했다. 회귀 모델은 뉴스킨 한 건에서 점수를 냈고 나머지 11건은 판정을 보류했다. 따라서 이 사례군으로 회귀 가중치의 실제 서비스 정확도를 추정하기 어렵다. 이전 합성 평가의 54/54는 해당 합성 자료에서의 결과다.

## 입력을 바꿔 확인한 점

의류 사례의 목록에서 취소선으로 표시된 정가를 빼고 판매가 하나만 입력해도 두 방식은 판정을 보류했다. 여기에 40,000원 배송비가 **필수이며 금액이 확정돼 있다는 조건을 가정**해 결제 레이어에 명시하자, 두 방식 모두 위험 신호를 표시했다. 이 경우 모델의 내부 점수는 0.99999였다. 이 실험은 원문 사례 12건의 집계에서 제외했다.

국내 가격 사례에서 가격과 주문 합계를 읽어도, 취소선 가격을 대표가와 구분하고 일반적인 배송 문구에서 필수 비용의 확정 여부를 확인하는 과정이 필요하다. 계층구조는 같은 화면이나 팝업 안에서 선택이 끝나는 경우를 현재의 목적지 기준으로 확인하기 어렵다. 사전선택은 두 유료 요금제 중 기본 설정과 0kg 수량 조절기처럼 라디오·체크박스 위주의 검사 범위를 벗어나는 사례가 있다.

`npm run eval:public`로 다시 실행한다. `npm run eval:public -- --json`은 케이스별 판정과 원점수를 출력한다.
